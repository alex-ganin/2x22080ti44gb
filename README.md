# 2× RTX 2080 Ti — локальный LLM- и речевой стек

Автономные сервисы вывода (inference) для **больших языковых моделей** и **распознавания речи с диаризацией спикеров**, работающие целиком на двухграфической рабочей станции. Без облачных круговых поездок, без SaaS — ваше железо, ваши веса, ваши данные.

> **22 ГБ + 22 ГБ = 44 ГБ видеопамяти** — вот в чём вся хитрость: это позволяет 27B-параметрической языковой модели и большой акустической модели поместиться на потребительских картах, которым в ином случае уже было бы десять лет.

## Структура репозитория

```
.
├── README.md                                ← вы здесь (рус.)
├── README.en.md                             ← английская версия
├── kvm.xml                                  ← локальный libvirt-профиль ВМ с GPU passthrough
├── qwen/                                    ← сервис LLM-вывода
│   ├── .env.example                         ← HF_TOKEN и пресеты MODEL
│   ├── Dockerfile                           ← кастомная sm75 + CUDA 13 сборка vLLM
│   ├── docker-compose.yml                   ← контейнер, ГПУ, тома
│   └── vllm-2080ti-sm75-cu130-wheels.tar.gz ← закреплённые колёса (vLLM + FlashQLA)
└── whisper/                                 ← сервис «речь → диалог»
    ├── .env.example                         ← HF_TOKEN, WHISPER_MODEL, DIARIZE_MODEL
    ├── Dockerfile                           ← WhisperX + faster-whisper + pyannote
    ├── app.py                               ← FastAPI + конвейер транскрибации
    └── docker-compose.yml                   ← контейнер, ГПУ, тома
```

Два соседних сервиса, каждый — самостоятельная сборка Docker. Они делят одни и те же два ГПУ и один и тот же кэш Hugging Face.

## Вспомогательные файлы

- **`kvm.xml`** — локальный libvirt-профиль ВМ `ubuntu26.04`: Ubuntu 26.04, 24 GB RAM, 6 статически закреплённых vCPU, passthrough обеих RTX 2080 Ti (8 PCI-функций) и модельный диск `MODEL.qcow2`. Это хостовая ВМ, а не Docker-сервис.

## Что построено и как

### 1. LLM-вывод — `qwen/`

Языковая сторона — это сервер **vLLM**, выставляющий 27B чат-модель за стандартным OpenAI-совместимым интерфейсом. Всё обслуживается локально; `GET /v1/models` объявляет её как `Qwen3.8`.

Ключевые решения сборки:

- **Кастомные колёса vLLM.** Встроенный vLLM не поставляет предварительно собранный билд для той комбинации, которую реально использует наше железо — Turing (sm75) в паре с CUDA 13.0. Вместо пересборки при каждом деплое мы фиксируем архив готовых колёс (`vllm-2080ti-sm75-cu130-wheels.tar.gz`, 38,4 MiB / ≈40.3 MB) и ставим его вместе с небольшим компаньоном `FlashQLA`, оба с `--no-deps`, чтобы закреплённый набор зависимостей оставался под контролем.
- **Выбор модели.** Текущий `MODEL` в `qwen/.env.example` — `shawnw3i/Qwen3.8-27B-AWQ-MTP`. Имя кодирует два важных свойства: **AWQ** (weight-4-activation-16, ~14 GB — комфортно в 44 GB VRAM с 128K-контекстом) и **MTP** (multi-token prediction — головка, которую vLLM использует для спекулятивного декодирования). В `.env.example` также есть закомментированные пресеты: `QuantTrio/Qwen3.6-27B-AWQ` (быстрый), `twolven/Qwen3.8-27B-abliterated-AWQ-MTP` (abliterated/uncensored) и `lued/Qwen3.8-27B-INT8-W8A16-MTP` (жёсткий INT8).
- **Конфигурация обслуживания.** Тензорный параллелизм 2, окно контекста **131 072** токенов, **94 %** видеопамяти зарезервировано под KV-кэш, включено **prefix caching** и спекулятивное декодирование с **3 черновыми токенами** на шаг через MTP-головку до верификации. Явная `--dtype` не задана — vLLM выбирает точность автоматически; attention — FlashInfer, разквантование AWQ — Marlin, reasoning parser — `qwen3`.

В итоге — HTTP-эндпоинт, с которым может говорить любой OpenAI-клиент без изменения конфигурации — нацелите его на локальный хост, и он будет вести себя так, будто говорит с облаком.

### 2. Распознавание речи — `whisper/`

Звуковая сторона — это сервис на базе **WhisperX**, превращающий загруженный диктофон в **транскрипт по ходам, где каждая строка атрибутирована спикеру**. Он выставлен как небольшое FastAPI-приложение с единственным эндпоинтом.

Конвейер, по порядку:

1. **Декодировать** загрузку в канонический формат через FFmpeg.
2. **Транскрибировать** через **faster-whisper** (CTranslate2-порт семейства Whisper) в точности `int8` на **ГПУ 0**. Развёрнутая модель — русско-настроенный турбо-вариант `dvislobokov/faster-whisper-large-v3-turbo-russian`; она переопределяется переменной окружения `WHISPER_MODEL` (дефолт кода — `Systran/faster-whisper-large-v3`).
3. **Принудительно согласовать** произведённые слова на звуковой таймлайн для получения словесных отметок начала/конца.
4. **Диаризовать** запись пайплайном **pyannote** `speaker-diarization-3.1` на **ГПУ 1** (это замкнутая модель Hugging Face, поэтому для деплоя требуется `HF_TOKEN`).
5. **Атрибутировать** каждое слово спикеру, наложив его временную метку на сегменты диаризации.
6. **Сгруппировать** идущие подряд слова одного спикера в реплики и вывести диалог.

Форма ответа намеренно проста, чтобы потребителям ниже по цепочке не приходилось моделировать внутренности:

```json
{ "dialogue": [ { "speaker": "SPEAKER_00", "start": 0.36, "end": 2.14, "text": "..." } ] }
```

Так как две тяжёлые стадии исполняются на отдельных ГПУ (распознавание на одном, диаризация — на другом), они могут накладываться на занятой машине — это осмысленное расчленение, продиктованное двухкарточной топологией.

## Быстрый старт

Предварительные условия: Linux-хост с NVIDIA-драйвером и `nvidia-container-toolkit`, Docker + Compose v2 и доступ Hugging Face (токен для замкнутых моделей).

### Языковой сервис

```sh
cd qwen

# Скопируйте шаблон переменных: HF_TOKEN + MODEL (текущий MODEL — shawnw3i/Qwen3.8-27B-AWQ-MTP)
cp .env.example .env
# отредактируйте .env и впишите HF_TOKEN

docker compose up -d --build
```

Подождите, пока модель не закончит грузиться на оба ГПУ (первый запуск скачивает и квантует; последующие — заметно быстрее). Затем прощупайте:

```sh
curl -s http://localhost:8000/v1/models
```

### Речевой сервис

```sh
cd whisper

# Скопируйте шаблон переменных: HF_TOKEN + WHISPER_MODEL + DIARIZE_MODEL
cp .env.example .env
# отредактируйте .env и впишите HF_TOKEN (обязателен для замкнутой pyannote-модели)

docker compose up -d --build
```

Речевой сервис опубликован на **хост-порту 8001**; внутри контейнера он слушает 8000.

Артефакты моделей (веса faster-whisper, pyannote, рантайм WhisperX) складываются в общий том кэша Hugging Face, так что сервисы не перезаваривают чужие нагрузки.

## Справочник API

### Язык — OpenAI-совместимо

Base URL `http://<хост>:8000/v1`, модель `Qwen3.8`.

```bash
curl -s http://localhost:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "Qwen3.8",
    "messages": [
      { "role": "system", "content": "You are a concise assistant." },
      { "role": "user",   "content": "Explain tensor parallelism in one sentence." }
    ],
    "temperature": 0.7,
    "max_tokens": 256
  }'
```

Вызов инструментов/функций использует схему `qwen3_xml` — модель выдаёт размеченный блок, описывающий инструмент и его аргументы, а клиент распарсивает и диспатчит.

### Речь — транскрибация

```bash
curl -s -X POST http://localhost:8001/v1/audio/transcriptions \
  -F 'file=@заседание.wav' \
  -F 'num_speakers=2'     # необязательная подсказка; опустите — пусть оценит сам
```

Возвращает диалог, описанный выше в разделе сервиса.

## Справочник конфигурации

Большинство ручек крутятся в соответствующем `docker-compose.yml`; пара — переменные окружения в рантайме.

### Язык (`qwen/`)

| Настройка | Значение | Смысл |
| --- | --- | --- |
| Модель | `shawnw3i/Qwen3.8-27B-AWQ-MTP` (текущий `MODEL` в `qwen/.env.example`) | 27B, AWQ, MTP; в `.env.example` также пресеты QuantTrio / twolven / lued |
| Обслуживаемое имя | `Qwen3.8` | Чем адресуют клиенты |
| Тензорный параллелизм | 2 | Распределить по обоим ГПУ |
| Точность | авто (явный `--dtype` отсутствует) | vLLM выбирает точность по модели |
| Контекст | 131 072 | Макс. токенов на последовательность |
| Одновременных последовательностей | 1 | Одна в полёте |
| Использование ГПУ-памяти | 0.94 | Сколько видеопамяти под KV-кэш |
| Prefix caching | включено | Переиспользовать повторяющиеся префиксы |
| Спекулятивное декодирование | MTP, 3 черновых | Набрать черновик и сверить |
| Reasoning parser | `qwen3` | Парсить reasoning-блок |
| Attention | FlashInfer | Бэкэнд внимания |
| Ядро кванта | Marlin | Разквантование AWQ |

`qwen/docker-compose.yml` передаёт в контейнер `MODEL_PATH=${MODEL}` и мапит `~/models:/models`, поэтому `MODEL` может быть как репозиторией Hugging Face, так и локальным путём внутри `~/models`.

### Речь (`whisper/`)

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `HF_TOKEN` | — | Токен Hugging Face (замкнутые модели) |
| `WHISPER_MODEL` | код: `Systran/faster-whisper-large-v3`; `.env.example`: `dvislobokov/faster-whisper-large-v3-turbo-russian` | Чекпоинт faster-whisper |
| `DIARIZE_MODEL` | `pyannote/speaker-diarization-3.1` | Чекпоинт диаризации |
| `BATCH_SIZE` | 16 в `app.py` | Размер батча для согласования; через compose не выведен |

## Модели и лицензии

| Сервис | Модель | Примечания |
| --- | --- | --- |
| Язык | `shawnw3i/Qwen3.8-27B-AWQ-MTP` (текущий `.env.example`) | 27B, AWQ W4A16 (~14 ГБ), MTP-голова; опциональные пресеты: twolven abliterated, lued INT8 |
| Речь (распознавание) | `dvislobokov/faster-whisper-large-v3-turbo-russian` | faster-whisper (CTranslate2), int8, русско-настроенный турбо |
| Речь (диаризация) | `pyannote/speaker-diarization-3.1` | Замкнутая модель Hugging Face; нужен токен |

Проверьте конкретную лицензию в карточке каждой модели на Hugging Face; несколько использованных здесь чекпоинтов некоммерческие или с обязательством указания авторства. Вариант `abliterated` — особенно комьюнити-производное, так что его лицензию следует считать тем, что декларируют базовая модель и сама операция abliteration.

## Зафиксированные версии

Воспроизводимость важна там, где единственная причина, по которой всё работает, — детали согласованы с ГПУ. Точные версии, определяющие работоспособную сборку:

**Язык:**

- Базовый образ `nvidia/cuda:12.6.0-devel-ubuntu24.04`
- Python 3.12 (virtualenv; системный Python защищён PEP 668)
- Torch `2.13.0` (+cu130)
- FlashInfer `0.6.16.post3`
- Transformers ≥ `5.5.3`
- vLLM + FlashQLA из закреплённого архива колёс

**Речь:**

- Базовый образ `nvidia/cuda:12.2.2-runtime-ubuntu22.04`
- Python 3.10
- Torch `+cu121`
- WhisperX (установлен из исходников — поддерживаемый форк)
- fastapi, uvicorn, python-multipart, ffmpeg

Закрепите их при форке; дрейф — то, как рабочая связка незаметно перестаёт быть таковой.

## Известные оговорки

- **Одна последовательность в полёте.** Языковой сервер настроен на одну одновременную последовательность (`max_num_seqs = 1`). Идеально для персонального эндпоинта и корректности; не заточено на многих пользователей сразу. Поднимите значение (и опустите контекст), если обслуживаете трафик.
- **Префиксное кеширование включено.** `qwen/Dockerfile` передаёт `--enable-prefix-caching`; повторяющиеся системные префиксы должны переиспользовать уже вычисленные состояния. При 128K-контексте и TP=2 стоит следить за VRAM/headroom.
- **Порты сервисов разделены.** `qwen` публикуется на хост-порту **8000**, `whisper` — на **8001** (внутри контейнера speech-сервис слушает 8000). Так оба Docker-сервиса могут работать одновременно на одном хосте.
- **Дефолты генерации берутся из чекпоинта.** Модель несёт собственный `generation_config.json`; температура, top-p, top-k и штраф повторности — ровно то, что в файле, пока запрос не переопределяет. Если вывод «как-то не так», начните с того файла, а не с подозрений к серверу.
- **Первый запрос платит за разогрев.** Совсем первое инференсирование после старта делает допработу (прогрев ядер/JIT). Ожидайте медленный старт, потом установившийся режим.
- **Шум на старте отчасти нормален.** Часть предупреждений при загрузке vLLM ожидаемы и безвредны — любопытные касаются рассогласований вычислительной способности ГПУ и бэкэнда внимательности.
- **Два разных CUDA-стека.** Языковой сервис исполняет сборку на CUDA-13, речевой — на CUDA 12.1. Это осмысленно (каждый закреплён под то, что поддерживает его набор зависимостей) и поэтому два `Dockerfile` выглядят не одинаково.
